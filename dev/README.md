# MCMetrics plugin dev Docker stacks

This folder contains isolated Docker Compose setups for each plugin type and the main server variants they need to run against.

## Quick start

```bash
cd dev
cp .env.example .env   # optional, but recommended for local Hoglin/server key overrides
./up.sh paper          # builds jars, syncs them into dev/plugins, then starts Paper
```

For a background run:

```bash
./up.sh velocity -d
```

To stop and delete the stack data for one setup:

```bash
docker compose -f compose.velocity.yml down -v
```

## Setups

| Setup | Compose file | Plugin artifact | Host port default | Notes |
| --- | --- | --- | --- | --- |
| Bukkit / Paper | `compose.bukkit-paper.yml` | `plugins/bukkit/MCMetrics.jar` | `25565` | Normal Paper server path. |
| Bukkit / Spigot | `compose.bukkit-spigot.yml` | `plugins/bukkit/MCMetrics.jar` | `25566` | Exercises the non-Paper Bukkit path; first boot may be slow while Spigot is prepared. |
| Bukkit / Folia | `compose.bukkit-folia.yml` | `plugins/bukkit/MCMetrics.jar` | `25567` | Exercises Folia scheduling support. |
| Fabric | `compose.fabric.yml` | `plugins/fabric/MCMetrics.jar` | `25568` | Installs Fabric API via Modrinth and mounts the MCMetrics mod into `/mods`. |
| Velocity | `compose.velocity.yml` | `plugins/velocity/MCMetrics.jar` | `25569` | Starts a Velocity proxy plus an offline Paper backend named `backend`. |
| BungeeCord | `compose.bungee.yml` | `plugins/bungee/MCMetrics.jar` | `25570` | Starts a BungeeCord proxy plus an offline Paper backend named `backend`. |
| Waterfall | `compose.waterfall.yml` | `plugins/bungee/MCMetrics.jar` | `25571` | Starts a Waterfall proxy plus an offline Paper backend named `backend`. |

## Jar sync

The compose files mount directories under `dev/plugins`. They intentionally do not mount `build/release` directly, because missing bind-mounted jar files can become directories and break Docker startup.

Run this after code changes:

```bash
./sync-jars.sh
```

`./up.sh` runs `./sync-jars.sh` automatically unless you pass `--no-sync` after the setup name.

## Hoglin/MCMetrics configuration

The plugin default config files are still generated by the plugin, but these stacks pass the key settings as JVM system properties:

- `MCMETRICS_API_SERVER`
- `MCMETRICS_SERVER_KEY`
- `MCMETRICS_<SETUP>_INSTANCE_ID`

Put local values in `dev/.env`. For testing against an API running on the host machine, set for example:

```env
MCMETRICS_API_SERVER=http://host.docker.internal:3000
MCMETRICS_SERVER_KEY=your-local-server-key
```

Each service includes `host.docker.internal:host-gateway` so host services are reachable from Linux Docker.

## Raw Docker Compose commands

You can also run the compose files directly:

```bash
cd dev
./sync-jars.sh
docker compose -f compose.fabric.yml up
docker compose -f compose.fabric.yml logs -f
docker compose -f compose.fabric.yml down -v
```

All compose files use unique project names, named volumes, and host ports so multiple stacks can run at the same time.


## E2E testing

The `dev/e2e` folder contains a TypeScript E2E harness. It uses `minecraft-protocol` for fake offline/cracked players and adds a Docker Compose `hoglin-api-proxy` service that mocks Hoglin while capturing all API calls for assertions.

```bash
cd dev
./sync-jars.sh
cd e2e
npm ci
npm run e2e -- paper
```

Run targets one at a time locally, or use the target list as a GitHub Actions matrix: `paper`, `spigot`, `folia`, `fabric`, `velocity`, `bungee`, and `waterfall`. The test matrix is capability-driven, so proxy targets do not run standalone-only chat listener tests.
